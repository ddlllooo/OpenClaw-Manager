镜像用途与资源分配（2026-10-16）

镜像用途
openclaw/openclaw 为实例运行镜像。openclaw-manager 为管理平台。
openclaw-base-node / openclaw-base-docker 为离线构建 Manager 所保留的基础镜像。
多个标签可能指向同一镜像 ID；镜像间也可共享层，不能将显示大小直接相加。
创建窗口只展示可识别的 OpenClaw 运行镜像。自定义运行镜像仍可手动输入。
本地镜像仓库按镜像 ID 展示用途和全部标签，不自动删除任何镜像或回滚容器。

预算
以 Docker 引擎报告的 CPU/内存容量为准。Desktop 的数值为虚拟机容量。
系统预留 CPU 为 max(0.5 核, 总量 10%)，向上取至 0.1 核。
系统预留内存为 max(512 MiB, 总量 10%)，向上取至 128 MiB。
然后扣除 Manager/其他运行容器上限和已有实例主容器上限。
已停止或 created 的主容器继续保留预算。停止的 rollback 副本不重复占预算；运行的副本仍计入。
已不存在容器的旧记录不占预算，启动/重启时重新校验。不会删除旧记录或改变现有实例配置。
Docker 实际上限高于记录时取较大值。有容器未设置上限时按该维度总容量计账并提示，不能保证其剩余容量。

推荐
CPU 取剩余预算的 1/4，通常在 1–2 核；受预算约束时可降至 0.5 核，向下取至 0.1 核。
内存优先 2 GiB，预算不足时向下取至 128 MiB，自动推荐最低 1 GiB。
进程上限 max(192, ceil(CPU) × 128)，不将虚拟机总核数作为实际线程数。
不足 0.5 核/1 GiB 时不给出自动推荐，不填入 Docker 中表示无限制的 0。
可手动填写预算内的较低上限；新提交 CPU 必须为正数，内存至少 64 MiB。
推荐是容量上限配置，不代表运行时占用或最低资源保障，也不根据某一瞬间的空闲值压缩现有实例。

并发与校验
创建、启动、重启和资源修改均重新读取预算。创建及修改使用同一进程内的分配锁。
镜像拉取期间以临时额度预留资源；失败后释放。已创建的容器仍按实际状态计账。
调整资源排除实例自身原有额度，避免重复扣减；Docker 更新失败不写入新记录。
历史超配允许逐步降低或保持已有维度，不允许继续增加。
其他 Docker 客户端仍可在平台之外改变容器资源，平台无法对外部操作提供事务保证。

发布
只重建/替换 Manager 容器，不停止、启动、重启或修改业务容器。
保留旧 Manager 镜像与源码备份便于回滚；不执行 image/container/system prune。
